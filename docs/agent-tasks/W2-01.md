## Codex architecture decision — 2026-09-25

- Keep one hidden PowerShell quota worker for the lifetime of the desktop pet. The worker owns one `codex app-server` stdio JSONL process and initializes that connection once. Normal repeated refreshes reuse it; a failed connection may be disposed and replaced on a later refresh. Do not introduce a listener, port, new credential source, or webpage scraping.
- The WPF dispatcher only sends a nonblocking refresh command to its worker and continues reading the existing atomically published `usage.json`. Never wait for an app-server line, a proxy timeout, or process shutdown on the UI tick. Permit at most one in-flight read; a manual refresh while a read is pending must be coalesced or queued once, not fork another worker.
- Use monotonic request IDs within each app-server connection. Match the response by ID, ignore unrelated notifications, reject malformed JSON, protocol errors, missing `result`, and EOF. Perform the documented `initialize` request followed by `initialized` once per connection. `clientInfo.version` identifies this pet client, not the negotiated app-server protocol version. Do not opt in to `experimentalApi`.
- Preserve the existing direct-first (12 seconds) and system-proxy fallback (25 seconds) behavior when a connection fails, plus `Set-UsageContract`, both quota windows, failure counters, stale-cache preservation, and atomic publication. Do not implement W2-02 reconnect backoff or W2-03 dynamic refresh timing.
- On timeout, exit, pet close, and forced worker replacement, release both the owned PowerShell worker and its Codex descendant. The parent must not depend solely on a graceful worker `finally` when killing a wedged worker. Keep preview/smoke mode free of online quota processes.
- Record a fake-app-server process-start count for two successful refreshes, a bounded failure/exit case, and the owned-process cleanup result. Record the local CLI version and initialization response capabilities without logging tokens, account details, raw credentials, or full server stderr.
- Official OpenAI documentation: https://learn.chatgpt.com/docs/app-server (stdio JSONL, request/response IDs, single initialize/initialized handshake, stable `account/rateLimits/read`). Local CLI observed: `codex-cli 0.155.0-alpha.16.4`; a sandbox warning about PATH alias creation appeared during `--version` but did not prevent the version response.
